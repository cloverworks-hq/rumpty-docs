<Endpoint method={"GET"} path={"/v1/git-connections/github-app/detect"} />

Inspects a repository branch and suggests how to build and run it: whether it is a `static`
site or a `service`, the framework, the root directory and the recommended build method.
The file list is inspected, plus a few `package.json` files for their dependencies and
workspace settings.

How detection works:

- The repository root wins when it holds an app. Other folders are checked only when the
  root has no app of its own, or the root is a JavaScript workspace with nothing but
  tooling. Folders such as `docs`, `examples`, `test`, `fixtures`, `scripts` and
  `.devcontainer` are skipped.
- Framework config files are recognised first, for example Next.js, Nuxt, Remix and
  SvelteKit (`service`), and Astro, Gatsby, Angular and Vite (`static`). Then Go, Rust,
  Laravel, PHP, Rails, Ruby, Java, Elixir and Deno projects (`service`). Then generic
  markers: `package.json` (refined by its dependencies), `requirements.txt`,
  `pyproject.toml`, `Pipfile`, `index.php` and `index.html`.
- A `Dockerfile` in the chosen folder makes `dockerfile` the recommended build method and
  sets `dockerfile_path`. `railpack` is always supported.
- A package of a shared JavaScript workspace (`pnpm-workspace.yaml` or `workspaces` in the
  root `package.json`, with the lockfile at the root) is built from the repository root:
  `root_directory` is empty, `monorepo` is `true`, and `build_command` and `start_command`
  target the package.
- When there is more than one app, `candidates` lists them, best first, each with the
  settings to deploy it. Ties are broken by common app folders (`apps/web`, `frontend`,
  `api` and so on), then by depth, then by name.

When nothing is recognised, `detected` is `false` and `recommended_build_method` is
omitted.

Requires the `secrets read` permission (owner, admin or developer role).

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Errors

| Status | Meaning |
|---|---|
| `400` | `repo` is missing or contains spaces. |
| `401` | The API key is missing, invalid, expired or revoked. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `404` | No GitHub account is connected, or none matches the repository's owner. |
| `500` | GitHub could not be reached, or the repository or branch is not accessible to the app. |

Errors use the [standard error format](/api#errors).
