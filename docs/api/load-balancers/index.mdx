A load balancer puts 1 to 10 of your VMs behind one HTTPS address,
`https://<name>-<id>.<domain>`. Requests are spread across the VMs that pass the health
check, round robin by default or pinned to one VM with a cookie when sticky sessions are on.
HTTP and gRPC backends are supported. You can limit which client IPs may connect with
`allowed_cidrs`.

Targets must be your VMs in the same workspace. A workspace can have up to 10
load balancers. Each one costs a flat $2 per month, billed hourly from creation until you
delete it. Billing pauses while the account is suspended for non-payment.

Every change is asynchronous. It returns `202 Accepted` with an `operation_id` and the load
balancer moves to `pending` until the change is live, then `ready` (or `failed` with
`last_failure`). See [Get an operation](/api/operations/get-an-operation). While a change is
`pending`, other changes return `409`. Deleting is always accepted: billing stops at once, and the
routing is removed as soon as the in-flight change finishes. Deleting a VM removes it
from every load balancer automatically.
