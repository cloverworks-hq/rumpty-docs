<Endpoint method={"POST"} path={"/v1/load-balancers"} />

Creates a load balancer in front of the given VMs. The hostname is derived from the name
and a short random id, for example `web-5d6e7f80.rumptycloud.app`.

Defaults: `target_protocol` `http`; health check `http` on `/` at the target port every 10
seconds with a 5 second timeout, 3 passes to become healthy and 3 failures to be ejected;
sticky sessions off (cookie `rumpty-lb`, 300 seconds when on); no IP restriction.

Send an `X-Idempotency` key to make retries safe. The key is tied to the name.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.

## Headers

<Param name={"X-Workspace-Slug"} type={"string"} required>

Slug of the workspace the request acts on. You can also pass it as the `workspace_slug` query parameter.

</Param>

<Param name={"X-Idempotency"} type={"string"}>

Optional unique key for this request, such as a UUID. Repeating a key for the same action
on the same load balancer returns the original operation with `200 OK` and
`X-Idempotency-Replay: true`, and nothing new is queued. Reusing it for a different action
or load balancer returns `409` with `action: idempotency_key_reused`.

</Param>

| Status | Meaning |
|---|---|
| `400` | Validation failed, for example `name is required`, `target_port must be between 1 and 65535`, `health_check.path must start with /`, or an invalid CIDR. |
| `401` | The API key is missing, invalid, expired or revoked. |
| `402` | The account is past due, so new paid resources cannot be created. |
| `403` | You cannot access the workspace, your role does not allow this action, or the account is suspended. |
| `404` | The resource does not exist or you cannot access it. |
| `409` | Conflict: the name or hostname is taken, the workspace already has 10 load balancers, a VM is being deleted, or the `X-Idempotency` key was used for a different operation (`action: idempotency_key_reused`). |
