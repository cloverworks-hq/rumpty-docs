<Endpoint method={"GET"} path={"/v1/load-balancers/{uid}/health"} />

Returns which targets are passing health checks and receiving traffic right now, with a
state for each target VM. A target is out when it fails the active health check or is
ejected after repeated errors.
The data is usually 15 to 45 seconds behind, depending on your health check settings;
`checked_at` is when it was read. Cheap enough to poll every 10 seconds.

`status` is `healthy` (all targets in), `degraded` (some out, including stopped VMs),
`down` (none in; clients get `503`), `no_targets`, or `unknown` when health data cannot
be read; see `unavailable_reason`. For a few seconds after a target is added or the
gateway restarts, a target can show as out until its first health check passes.

## Authentication

Send your [API key](/api#authentication) as `Authorization: Bearer <token>`. The request is scoped to the workspace in `X-Workspace-Slug`.
